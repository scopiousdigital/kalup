`kalup add` and `kalup blueprint upgrade`: blueprints from a local file or an `https` URL, rendered into config through the canonical writer. Neither command sends a HubSpot request; the portal changes go through `plan` and `apply`.

- `kalup add <source> [--prefix <p>] [--dry-run]` reads the blueprint (a URL fetch sends no key, follows redirects only to https, stops after 30 seconds or 1 MB), hashes the bytes, validates it and applies the prefix (`--prefix`, else config's `prefix`). A resource config already has with the same definition and binding is recorded, one with another definition is `E_BLUEPRINT_COLLISION`. It writes the resources into the export that holds their object or a new object file, adds missing objects to `kalup.config.ts`, regenerates the barrel, records the blueprint in `kalup/blueprints.lock.json` and stores the fetched bytes under `kalup/.blueprints/`. The same source and version with other bytes is `E_BLUEPRINT_INTEGRITY`; a blueprint already added is `E_BLUEPRINT_ADDED`.
- `kalup blueprint upgrade <name> <source> [--take remote <address[#unit]>]... [--dry-run] [--exit-code]` merges three ways, with the stored original as base, config as local and the new version as remote, unit by unit. Upstream changes land where the client left the unit alone; the client's changes stay; a unit both changed differently is a conflict that keeps config, is held in the lock, and `--take remote` resolves. Options merge by value; an option removed upstream stays with a note; what the client removed stays removed; a resource removed upstream is detached, never deleted. Overrides are untouched. `W_BLUEPRINT_DOWNGRADE` warns about a lower version.
- Both validate the project as they would leave it (exit 3 on any issue) and write every file through the shared staged write, which puts every file back on a failure (`E_PROJECT_WRITE`) and removes an old stored original only after every rename succeeded.
- New codes: `E_BLUEPRINT_SCHEMA`, `E_BLUEPRINT_LOCK`, `E_BLUEPRINT_SOURCE`, `E_BLUEPRINT_INTEGRITY`, `E_BLUEPRINT_ADDED`, `E_BLUEPRINT_COLLISION`, `E_BLUEPRINT_REF`, `E_BLUEPRINT_REQUIRES`, `E_BLUEPRINT_UNKNOWN`, `E_BLUEPRINT_ORIGINAL`, `W_BLUEPRINT_DOWNGRADE`. Third-party text is sanitized wherever it is quoted, and the description is printed only to a person at a terminal, labelled as the blueprint's own text.
- New shipped page `docs/blueprints.md`, listed in the AGENTS.md docs index.
